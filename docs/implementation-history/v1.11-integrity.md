## Proposed short release note

**CHANDRA v1.11.0 — integrity release.** Analysis identity is now exact:
the cache, export guard and SHA-256 fingerprint share a canonical,
full-precision serialization of the site, millisecond UTC window and config
(no rounding). Fingerprint values change across this release; the report
schema stays `2.0.0`. Persisted briefing sessions are size-checked before
`JSON.parse` (800,000 UTF-16 code units) with an explicit, dismissible recovery
notice. Coarse energy integration (estimated relative error ≥1%) is allowed for
research but carries `ENERGY_RESOLUTION_COARSE` through the UI, JSON warnings,
CSV disclosures and comparisons. No integration equation or threshold changed.
Not flight software.

## Scope

Priority-0 fixes only, plus validation/documentation infrastructure:

1. **Exact `simulationKey`.** `canonicalJson.ts` sorts object keys, preserves
   array order and full double precision, and rejects non-finite/sparse/cyclic/
   non-JSON inputs. Internal identity tag `chandra-analysis-v2`. LRU remains 36.
   Fingerprint values break; opaque field format and schema do not.
2. **Session size cap.** `MAX_SESSION_LENGTH = 800_000` checked before parse and
   before save; `SESSION_TOO_LARGE` recovery notice persists until dismissed;
   save/storage failures are returned, not swallowed. Validation and v1→v2
   revalidating migration unchanged. The cap is a parser-work budget, not a byte
   cap and not the theoretical structural maximum.
3. **Coarse energy disclosure.** Shared `energyResolutionDisclosure()` helper;
   persistent telemetry/comparison notes; JSON warnings; existing CSV
   disclosure columns; comparison warnings; timeline a11y text. Policy:
   allow-with-strong-warning, not a silent block. Richardson estimate is not a
   confidence interval; energy balance is not thermal survival.
4. **Validation infrastructure.** Optional canonical-key benchmark; optional
   `workflow_dispatch` real-DEM fixture smoke (third-party gap-filled software
   downsample, not a required check); real-DEM harness dismisses first-run
   onboarding and supports CI Chromium; manual screen-reader protocol with
   expected results (still not executed).
5. **Product design deliverable.** Landing/workspace entry specification in
   [../product-design.md](../product-design.md) — design only, not shipped.
