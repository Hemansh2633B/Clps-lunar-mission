# v1.12.0 · native backend and lunar data

> Release report, written at release time. For current behaviour read the root
> README and [../verification.md](../verification.md). Branch:
> `arena/0f3b6dab-clps-lunar-mission`, base merged v1.11 `9b77277`.

## Short release note

**CHANDRA v1.12.0 — native backend and lunar data.** The optional Python
backend is replaced by a Go API with no dependency outside the standard
library, which deploys with the console as a single Vercel function. The south
pole map is redrawn in the correct orientation and can overlay NASA Moon Trek
and LROC imagery. A Lunar Data Hub lists every source with its provenance,
compares the ephemeris with NASA/JPL Horizons, and the Terrain Lab can fetch
subsets of NASA LOLA polar DEMs by HTTP range requests. The JSON report schema
becomes `2.1.0` (additive). Not flight software. **No live deployment and no
call to a NASA, JPL or LROC service was made during development**; see
verification.md for exactly what was and was not exercised.

## What changed

1. **Backend rewritten in Go.** `backend/geotiff` (GeoTIFF/BigTIFF reader and
   subset writer), `backend/lunarcrs` (spherical lunar projections),
   `backend/terrain` (validation, extraction, horizon), `backend/frames`,
   `backend/horizons`, `backend/lola`, `backend/store`, `backend/catalog`,
   `backend/httpapi`; `cmd/chandra-api` and `api/index.go` wrap one handler.
   The v1.11 routes keep their contract (additive fields only); five routes are
   new. Python is gone from the application, its tests and its deployment;
   `tools/spice-evidence/` remains as an optional offline evidence generator.
2. **Reference recorded before removal.** The Python backend's behaviour —
   GDAL-written rasters, PROJ values, extractions, horizons and 111 API calls —
   is frozen in `tests/golden/` and the Go tests compare against it.
3. **Polar Map.** One projection module; orientation corrected (0° up); five
   zoom levels; bundled mosaic always underneath; Moon Trek WMTS and LROC WMS
   layers placed by computation from their capabilities; explicit layer status.
4. **Lunar Data Hub.** Catalogue of 20 sources and 10 CSA references with
   *Not confirmed* for anything not read from the provider; JPL Horizons
   verification, live and recorded.
5. **LOLA acquisition.** Bounded, range-only, allowlisted, with provenance and
   checksum; datasets selectable in the Terrain Lab.
6. **Exports.** Schema `2.1.0`: `dataProvenance` block and optional
   `horizonProfile.sourceProvenance`; `ephemeris.model` no longer implies a JPL
   numerical ephemeris.
7. **Vercel.** `vercel.json`, `.vercelignore`, CSP, storage adapters, and
   `scripts/vercel-check.mjs`, which validates the configuration and executes
   the built function locally.
8. **CI.** Four jobs; a Go toolchain step; the data-feature browser suite.

## Decisions worth recording

- **Go, not Rust.** Go could be built and tested end to end in the development
  environment; Rust could not be built there at all. A standard-library-only
  backend also removes dependency risk from the deployment. This is a
  constrained engineering decision, not a benchmark
  ([architecture](../architecture/overview.md)).
- **A closed reader instead of GDAL.** Neither language has GDAL or PROJ
  natively. The reader accepts a listed set of layouts and projections,
  reproduces GDAL on that set, and refuses everything else.
- **Exact transforms.** The native engine transforms every cell exactly where
  v1.11 used GDAL's approximate transformer, so v1.12 terrain is not
  numerically identical to v1.11's (up to a few metres per cell on rough
  terrain). The difference is measured and equals GDAL's own exact-versus-
  default spread ([scientific-method §14.4](../scientific-method.md)).
- **Imagery is never data.** Tiles go from provider to `<img>`; nothing reads
  them back.
- **Unknown stays unknown.** Catalogue fields not confirmed from the provider
  are `null`.

## Found along the way

The v1.11 Polar Map drew markers mirrored north–south against its imagery, and
the v1.11 export called the engine a "JPL DE402/DE421-class ephemeris". Both
are corrected. Seven further defects were introduced and caught within v1.12
development by its own verification; they are listed in
[../known-issues.md](../known-issues.md) because the tests that caught them
remain.

## Verification

Executed evidence, the environment's limits and the list of what remains
unverified are in [../verification.md](../verification.md). In brief: 368 unit
tests, 77 Go tests with 30 subtests, geometry and parity checks, a Vercel build
executed locally, and five browser suites passed locally under software
rendering; GitHub Actions passed all four jobs on the pushed commit; nothing
was verified against a live deployment or a live external service.

## Owner actions

- Deploy: import the repository in Vercel or run `npx vercel`
  ([../deployment/vercel.md](../deployment/vercel.md)); optionally connect a
  Blob store so acquired DEMs persist.
- Run `CHANDRA_LIVE_TESTS=1 npm run test:go` once from a machine that can reach
  NASA PGDA and JPL Horizons.
- Open each remote imagery layer once in a normal browser and confirm it
  registers with the graticule.
- Branch protection: the CI check names changed
  ([../ci-governance.md](../ci-governance.md)).
